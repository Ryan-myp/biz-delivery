# biz-delivery 架构优化方案

> 针对当前 biz-delivery 架构的问题，提出优化方案。

---

## 现状分析

### 核心组件
| 组件 | 行数 | 状态 |
|------|------|------|
| learn_repo.py | 5,315 | ✅ 稳定 |
| review_engine.py | 3,011 | ✅ 稳定 |

| td_engine.py | 460 | ⚠️ 待废弃 |

### 主要问题

1. **TD 引擎功能不完整**
   - v1 两步调用，v2 单步调用，但 LLM 调用依赖环境变量
   - 缺少错误处理和降级策略

2. **测试引擎过于简单**
   - 只有 770 行，功能有限
   - 缺少正向/异常/边界用例全覆盖

3. **缺少端到端集成测试**
   - 没有自动化测试验证完整流程
   - 各引擎间数据传递依赖手动

---

## 优化方案

### Phase 1: TD 引擎完善（优先级 P0）

**目标**：将 td_engine_v2.py 从 427 行扩展到 1500+ 行

**功能增强**：
1. 支持多轮对话（用户反馈后迭代优化）
2. 内置示例库（基于历史优秀 TD 模板）
3. 错误重试机制
4. 详细日志输出

### Phase 2: 测试引擎增强（优先级 P1）

**目标**：将 test_engine.py 从 770 行扩展到 2000+ 行

**功能增强**：
1. 正向用例：基于 PRD 主流程生成
2. 异常用例：权限不足、数据校验、系统异常
3. 边界用例：空数据、极值、并发
4. 接口用例：状态码、响应结构、错误码

### Phase 3: 端到端集成（优先级 P2）

**目标**：建立完整测试流程

1. 集成测试：PRD → Review → TD → Test Cases
2. 质量评估：自动生成质量报告
3. 对比分析：与人工编写方案对比
